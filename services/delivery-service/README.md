# 🚚 Delivery Service

**Сервис доставки уведомлений**. Отвечает за потребление сообщений из очереди, применение стратегий маршрутизации и физическую отправку уведомлений через каналы **Bitrix24** и **Email**.

> ⚡ **Архитектурная роль**: Сервис является «воркером» платформы. Он не имеет публичного API для приёма данных (кроме healthcheck), а работает в фоновом режиме, обрабатывая события, поставленные сервисом `receive-service`.

---

## 🚀 Основные возможности

- **Strategy-Based Routing**: Гибкая логика доставки на основе стратегий (`send_to_first_available`, `send_to_all_available` и др.), определяющая поведение при работе с несколькими каналами.
- **Channel Extensibility**: Модульная архитектура каналов: новые провайдеры (SMS, Telegram, Push) подключаются через общий интерфейс без изменения ядра.
- **Async Queue Processing**: Надёжное потребление сообщений из AMQP-очереди и обработки ошибок.
- **Observability**: Полная трассировка процесса доставки, сбор метрик по каждому каналу и стратегиям, структурированное логирование результатов.

---

## ⚙️ Стратегии доставки

Поведение при отправке в несколько каналов определяется полем `strategy`:

- `send_to_first_available` — отправка прекращается после успеха в **первом** доступном канале.
- `send_to_any_available` — успех, если доставлено **хотя бы в один** доступный канал; ошибка, если все неудачны.
- `send_to_all_available` — успех, если уведомление доставлено **по всем** указанным каналам; ошибка, если хотя бы один канал вернул сбой.

> 📘 С полным описанием алгоритмов и диаграммами состояний вы можете ознакомиться в документе [strategies.md](../../docs/architecture/strategies.md).

## 📡 Интерфейсы взаимодействия

Сервис не предоставляет HTTP API для бизнес-операций. Взаимодействие происходит исключительно через брокер сообщений.

### Входные данные (Consumer)

Сервис подписывается на очередь (например, `notifications`) и потребляет сообщения в формате, определенном в `@notification-platform/core`.

```json
{
  "id": "uuid-123",
  "createdAt": 12345,
  "contacts": [
    { "type": "bitrix", "value": 4582 },
    { "type": "email", "value": "user@company.com" }
  ],
  "message": "Заказ #123 готов",
  "strategy": "send_to_first_available"
  //...
}
```

## 🩺 Healthcheck

Сервис предоставляет стандартные эндпоинты для оркестраторов:

- **Liveness**: `GET /health/live` — процесс жив.
- **Readiness**: `GET /health/ready` — все зависимости доступны.

Используйте в `livenessProbe` / `readinessProbe` Kubernetes.
